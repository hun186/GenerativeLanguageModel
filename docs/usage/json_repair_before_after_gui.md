# Windows GUI：JSON 修復前後差異

在 Processing Quality／異常監控的品質摘要下方，展開「JSON 修復前後差異（最近案例）」。
此介面展示當次執行的分類總數與最多 12 個最近成功修復的比較案例：
時間、切片短雜湊、推測類型、前後字元數、原始解析錯誤位置、
字面值相同率、鍵名樣式數，以及選取案例的共同前綴／後綴長度。
不直接顯示原始或修復 JSON，也不分析交錯的 Worker stdout。

## 分類說明

- 疑似符號修補：字串、數值等字面值序列未見變化，可能只補逗號或括號。
- 疑似尾端補全：原始字串未結束，修復輸出從原文前綴接續；不能判定來源已截斷。
- 內容有變動：字串／數值字面值已有差異。
- 內容大幅變更：字面值相同比例偏低或前後長度差較大。
- 無法可靠比較：文字超過 160,000 字、詞法項目超過 3,000 或其他限制。

以上都是詞法啟發式分類，不是語義驗證、Event／Event_Timeline 完整性測試，
也不代表所有資料被正確保留。錯誤位置為原始 JSON 解析失敗的大致位置；
欄位樣式數為近似值，字數非 token 數。

## 安全與資料流

比較在同一個 PromptAPIPipeline Worker 內取得原始與成功修復的真實字串後，
只把固定類型與嚴格數值欄位寫入原有 processing_quality_events JSONL。
不儲存 JSON 原文、Prompt、API key 或端點。GUI 沿用原有背景讀取、
事件封存與完整性檢查；修復診斷例外不能影響任務結果。

既有「初次 JSON 不合法率」與「修復成功率」維持不同事件／嘗試分母。
修復失敗沒有可解析 after，不生成比較事件；以前已完成的舊任務無法回補。
品質檔案失去完整性驗證時，GUI 不顯示歷史統計為已驗證結果。
本功能不變更 Prompt、模型重試、Queue 或 SQL／ES 寫回語義。
