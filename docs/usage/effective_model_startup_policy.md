# Effective model startup policy

The shared SQL/ES/Table runtime logs `[Effective Model Configuration]` after UI setup and before workers launch. This reads the actual job context and the existing request/round/worker policy resolvers. The profile worker budget and the context worker budget are displayed separately, so a later override is visible. Endpoint count is the distinct configured endpoint count in the final context, not an independent health probe. Explicit zero retries are shown as zero; absent HTTP read or retry controls show client/SDK default rather than a guessed value. A round deadline is not provider cancellation, and a lease cap is not measured server concurrency. The log never dumps model specification, endpoints, API credentials, or prompt text. Unsupported/invalid policy is shown as unavailable without exception contents. This is a startup observation, not an attestation of every subsequent call or multistage override. Provider reasoning support remains unverified.
